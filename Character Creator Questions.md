# Character Creator Mockup — Design Questions

**For:** Claude Project Manager
**From:** Claude Design
**Re:** Phase 2 Character Creator — pre-mockup design questions
**Context:** Before I produce the hi-fi mockup of the home page, Screen 2 (path choice), and the eight creator steps, I need a handful of decisions to scope and direct the work. Each question has suggested options; feel free to answer with one of the options, a combination, or freeform notes.

---

## 1. Scope — which screens should the mockup cover?

The spec covers 10 screens total: home page, Screen 2 (path choice), and the eight creator steps.

- [ ] **All 10 screens** — full prototype, every step rendered
- [ ] **Hero set** — Home, Path choice, Steps 2 / 4 / 5 / 7 (the most distinctive screens; skip the lighter steps)
- [ ] **Just the 8 creator steps** — skip home and path choice
- [ ] **Decide for me**

---

## 2. Mode focus — manual, handoff, or both?

Handoff mode adds the distinctive UI: celebration cards (Steps 2, 3, 5), narrative-continuity copy (Step 4), use-name affordance (Step 1), heirloom candidate picker (Step 6), and the Step 8 callout. Manual mode is the cleaner baseline.

- [ ] **Both** — toggle between them per step (recommended for review)
- [ ] **Handoff mode only** — the more distinctive of the two
- [ ] **Manual mode only**
- [ ] **Decide for me**

---

## 3. Aesthetic direction

This is a fantasy RPG creator — there's room to lean in. The spec's voice ("the years that shaped you," "in the years behind you") rewards a literary register.

- [ ] **Atmospheric & fantasy** — parchment / ink / serif, evocative, manuscript-fragment feel for celebration cards
- [ ] **Modern dark** — slate + gold accents, RPG-feel but clean and contemporary
- [ ] **Editorial & literary** — tall serif typography, generous whitespace, calm, prestige-novel register
- [ ] **Explore a few options as Tweaks** — pick one as default, expose the others
- [ ] **Decide for me**

---

## 4. Data fidelity — how real should the content be?

- [ ] **Fully populated** — real themes, classes, races, ancestry feats, and the §7 prompts from the spec rendered verbatim
- [ ] **Mostly populated** — real where it matters; placeholders where the spec gets long (e.g., showing 3 of 21 themes in pickers, not all 21)
- [ ] **Lightly populated** — focus on layout and hierarchy; lorem-style content
- [ ] **Decide for me**

---

## 5. Interactivity level

- [ ] **Fully clickable wizard** — Next/Back works, fields persist, dismissable cards dismiss, dropdowns populate, Step 8 review reflects real prior-step state
- [ ] **Mostly static** with a few key interactions (open expansions, dismiss the narrative-continuity card, swap modes)
- [ ] **Static screens only** — design comp only, no behavior
- [ ] **Decide for me**

---

## 6. Celebration card tone

These appear in handoff mode above locked fields (Steps 2, 3, 5), honoring what shaped the character.

- [ ] **In-fiction & evocative** — rendered like a manuscript fragment with chapter beats as italicized prose
- [ ] **Card-like UI block** — chapter beats as a clear bulleted list, the locked outcome called out structurally
- [ ] **Both** — show one as default, offer the other as a tweak
- [ ] **Decide for me**

---

## 7. Tweaks — which knobs should the prototype expose?

Tweaks are the in-design controls the user can toggle to compare variants without leaving the page.

- [ ] **Aesthetic toggle** — parchment / dark / editorial
- [ ] **Mode toggle** — manual / handoff (per step)
- [ ] **Density toggle** — compact / spacious
- [ ] **Show / hide help text**
- [ ] **All of the above**
- [ ] **Decide for me**

---

## 8. Target viewport

- [ ] **Desktop only** (~1280–1440 wide)
- [ ] **Desktop + mobile responsive**
- [ ] **Decide for me**

---

## 9. Standard Array UX (Step 5)

The spec explicitly asks Design to propose a treatment that beats the existing dropdown-per-score pattern.

- [ ] **Draggable chips** — six values sit in a pool above six ability rows; player drags a chip onto an ability
- [ ] **Click-to-claim** — chips fixed in position; abilities pull them in via a "claim" affordance
- [ ] **Show both side-by-side** as design options
- [ ] **Decide for me**
